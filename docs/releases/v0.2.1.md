# 0.2.1 connection retention verification

Checked 2026-10-13. Version code 5, same application ID and release signing
identity as 0.1.1/0.2.0. Release: [v0.2.1](https://github.com/RazvanManolache/herdr-on-the-go/releases/tag/v0.2.1).

The paired Windows listener previously closed a stream after 60 seconds without
an incoming frame. Authenticated idle reads now survive that timeout, while
incomplete frames, stalled writes, authentication, and revocation remain bounded.
The input reader uses socket reads directly because Python's buffered file reader
cannot safely resume after a timeout.

Android sends an empty inactive subscription every 20 seconds and waits at most
15 seconds for its matching acknowledgement. This works with the existing paired
bridge. Snapshot events cannot serve as acknowledged keep-alives because they
carry no request ID. Keep-alives run separately from the controller's work queue.

After a transport interruption, the controller reconnects to the same pinned PC
and selected session, with two-to-30-second retry delays. It retains the selected
pane and drafts and restores read subscriptions. It does not replay mutations.
Manual Disconnect cancels recovery; revocation, changed certificates, protocol
errors, and unavailable sessions require attention.

disposable; only the explicitly selected test emulator was changed. The work PC
and physical phones were not modified. Android background execution remains
best-effort while the process is allowed to run; there is no foreground service.
Reopening the app resumes pending connection recovery.
